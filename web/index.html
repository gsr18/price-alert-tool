TRANSPARENT BY DESIGN

How the rules work

The browser evaluates each observation locally, in date order, separately for each instrument.

01 / LEVEL

Cross a chosen level

Above: previous close is at or below the level; current close is above.

Below: previous close is at or above the level; current close is below.

A first observation cannot cross. Touching the level alone is not an alert.

02 / MA_CROSS

Compare moving averages

Above: short average moves from at-or-below to above the long average.

Below: short average moves from at-or-above to below the long average.

Both comparison points need full windows. Calendar gaps do not interrupt observation order.

RULE FORMAT

Official JSON shape

[
  {"id":"r1","instrument":"INFY",
   "type":"level","direction":"below",
   "level":1500},
  {"id":"r2","instrument":"TCS",
   "type":"ma_cross","short":5,
   "long":20,"direction":"above"}
]

Legacy threshold and shortWindow/longWindow aliases are also accepted. If both alias names are present, they must agree.

ABOUT THIS DEMO

A clearer view of
configured conditions.

Price Alert Studio demonstrates historical rule evaluation from the Price Alert Tool project. It is a separate, client-side JavaScript implementation of the Java CLI logic; the Java JAR does not run in the browser.

Important: Historical alerts are not predictions, investment advice, or recommendations. A signal only means that a configured condition was present in the supplied data.

LOCAL / STATIC
Your files→Browser parser→Rule engine→Verifiable alerts

No upload server, market feed, analytics, or remote storage. The Java CLI and Maven test suite remain separate.
